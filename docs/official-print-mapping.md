# تطبیق چاپ‌های رسمی با نمونه‌های اکسل

مبنای فرم‌ها، فایل‌های ارسالی «سند ۸۰۸»، «سند ۷۵۹»، «پیش‌پرداخت ۴۲۰» و «پیش‌پرداخت تنخواه ۴۹» است. چیدمان HTML برای چاپ A4 سیاه‌وسفید از جدول‌ها و ناحیه‌های امضای همان نمونه‌ها پیروی می‌کند. فایل‌های Excel و فرمول‌های آسیب‌دیدهٔ آن‌ها در زمان اجرای سامانه لازم نیستند.

| فرم و سلول نمونه | دادهٔ آمادبان |
| --- | --- |
| سند T2 | شماره سند خودکار |
| سند Z2 | یک روز شمسی پیش از تاریخ فاکتور |
| سند F3 | شماره فاکتور |
| سند C10 | تاریخ فاکتور |
| سند V10 | نام فروشنده |
| سند Y49 | `پ ` و شماره پیش‌پرداخت؛ برای نقدی خالی |
| سند F52 و O53 | تاریخ فاکتور فقط در صورت ورود به انبار؛ در قالب ۷۵۹ به‌دلیل جابه‌جایی ردیف، محل متناظر F51 و O52 است |
| پیش‌پرداخت K4 / K5 / K6 | شماره پیش‌پرداخت بدون «پ» / تاریخ فاکتور / شماره فاکتور |
| پیش‌پرداخت C16 / E16 | شماره کد اعتباری / عنوان فارسی آن |
| پیش‌پرداخت G16 | نام قلم نخست و قلم آخر فاکتور، با خط فاصله بینشان |
| پیش‌پرداخت G17 / K17 / G18 | شبا / بانک / صاحب حساب؛ برای شخص حقیقی نام فروشگاه در پرانتز |
| پیش‌پرداخت H22 | شماره سند مرتبط؛ در پیش‌فاکتور پیش از صدور سند خالی |
| صورت‌جلسه | جدول ۱۴ ردیفی، جمع عددی و حروفی، کارشناس همان سند، رئیس آماد، افسرعامل و امضاکنندهٔ اختیاری |
| تنخواه | همان ساختار پیش‌پرداخت، با شماره فاکتور دستی و کد اعتباری خالی |

نام قلم در چاپ سند از متن فاکتور می‌آید و نام کالای انبار جایگزینش نمی‌شود. امضاها از اشخاص تعریف‌شده و درجهٔ آن‌ها خوانده می‌شوند. محل «کارشناس / رئیس قسمت» در هر سند از شخص منتخب همان بخش پر می‌شود. بخش گیرندهٔ وجه در نمونهٔ پیش‌پرداخت یک متن گواهی چاپی است و نقش امضاکنندهٔ مستقلی در سامانه ایجاد نمی‌کند.

بررسی انجام‌شده با Chromium 109 روی پایگاه دادهٔ آزمایشی جدا: چاپ سند اعتباریِ دارای دو قلم، پیش‌پرداخت متصل، تنخواه و صورت‌جلسه همگی HTTP 200 و PDF تک‌برگ A4 تولید کردند. این بررسی جانشین آزمایش با چاپگر واقعی بیمارستان نیست.
